# CNEXT-CAM 设计方案

> 版本：1.0　　日期：2026-05-19

---

## 1. 设计原则

### 1.1 与 Mastercam 的对比定位

| 维度 | Mastercam | CNEXT-CAM |
|------|-----------|-----------|
| 目标用户 | 专业 NC 程序员 | 职业院校学生、工厂新手 |
| 界面复杂度 | 高（Ribbon + 多面板同时显示） | 低（单主窗口，渐进式参数） |
| 学习周期 | 数周到数月 | 1 天内上手核心功能 |
| 参数数量 | 数十项/工序（含大量高级选项） | ≤ 5 项必填，高级选项默认折叠 |
| 多轴支持 | 完整 3~5 轴 | 仅 2.5D（当前版本） |
| 后处理 | 数百种控制器 | Siemens 840D（首期） |
| 算法依赖 | 商业内核 | 完全自包含，无外部库 |

### 1.2 UX 简化策略（来源：Fusion 360/Easel/Carbide Create 最佳实践）

1. **任务向导化**：每个加工类型以向导形式引导，用户不会迷失在全局菜单中。
2. **智能默认值**：根据孔径、材料自动填充转速、进给，用户只需确认或微调。
3. **即时可视化**：每次参数修改后，刀路在三维视口实时更新（当前版本为生成后刷新）。
4. **渐进式复杂度**：基本模式只显示 3~5 个必填参数；专家模式展开全部选项。
5. **错误前置**：在生成 G 代码之前校验刀具匹配、孔径合法性，而不是在机床上报错。

### 2.2 核心数据流

```
STEP文件
  → StepImporter（OCC BRep → 三角面网格 + 拓扑图）
  → TopoAnalyzer（构建 AAG 邻接属性图）
  → FeatureRecognizer（模式匹配 → MachiningFeature[]）
  → FeatureListPanel（UI 展示）
  → 用户勾选特征
  → StrategyPanel（选择策略 + 填写参数）
  → Strategy::generate() → 中间 G 代码（含 ;CNEXT_HOLE_CYCLE 元数据）
  → PostProcessor::wrapGCode() → 目标 G 代码（MCALL CYCLE83 等）
  → GCodeEditor（显示） + SimulationController（仿真展开）
```

## 3. 模块设计

### 3.1 特征识别模块

**目标**：从 STEP 几何中自动识别所有可加工特征，减少用户手动定义工作量。

| 类 | 职责 |
|----|------|
| `TopoAnalyzer` | 构建面邻接属性图（AAG），标记凹/凸边 |
| `FeatureRecognizer` | 基于 AAG 做模式匹配，识别孔/槽/型腔/凸台/倒角/圆角/平面 |
| `FeatureClassifier` | 对孔候选做子类型细分（通孔/盲孔/沉头孔/螺纹孔） |
| `HoleStrategyUtils` | 孔几何计算工具（孔口Z、进给起点Z、有效深度、啄钻步距） |

**关键识别逻辑**：
- 圆柱面 + 两侧轴向平面开口 → 通孔
- 圆柱面 + 一侧平面盖面（无相对开口） → 盲孔
- 圆锥面 + 圆柱面组合 → 沉头孔 / 倒角孔
- 封闭平底 + 周围侧壁凹边 → 槽或型腔（按侧壁数量和形状细分）

### 3.2 策略模块

**设计原则**：策略只负责生成中间格式 G 代码，不直接输出控制器特定语法。

```
StrategyBase
├── HoleStrategyBase
│   ├── SpotDrillingStrategy    → CNEXT_HOLE_CYCLE code=G81/G82
│   ├── PeckDrillingStrategy    → CNEXT_HOLE_CYCLE code=G83
│   ├── DeepHoleDrillingStrategy → CNEXT_HOLE_CYCLE code=G83
│   ├── TappingStrategy         → CNEXT_HOLE_CYCLE code=G84
│   ├── ReamingStrategy         → CNEXT_HOLE_CYCLE code=G85
│   ├── ChamferStrategy         → CNEXT_HOLE_CYCLE code=G82
│   └── HoleCircularMillingStrategy → 圆插补 G02/G03
└── MillingStrategyBase
    ├── FaceMilling             → 行切 G1 段
    ├── PocketRoughingStrategy  → 行切清腔（矩形/圆形型腔自适应）
    └── ContourFinishStrategy   → G41/G42 轮廓 + 引入/引出
```

**批量接口**：所有孔策略同时实现 `generate(HoleFeature)` 和 `generate(QVector<HoleFeature>)` 两个重载，后者按最近邻 TSP 排序后批量输出，合并换刀和主轴启动块。

### 3.3 后处理模块

**两阶段流水线**：

```
策略输出（中间格式）                    后处理输出（控制器语法）
;CNEXT_HOLE_CYCLE code=G83              MCALL CYCLE83(rtp, rfp, sdis, dp, dtb, mdep, vari)
  rtp=50 rfp=0 sdis=3                   X10.000 Y20.000
  x=10 y=20 z=-30                       X30.000 Y40.000
  q=2 p=0.3 f=40                        MCALL
```

**扩展性**：`PostProcessorRegistry` 单例注册，新增后处理器只需实现 `PostProcessorBase` 接口并调用 `registerPostProcessor()`。

### 3.4 仿真模块

`SimulationController` 解析后处理输出的 G 代码，将 MCALL CYCLE 指令展开为仿真路径：

| 循环类型 | 展开逻辑 |
|---------|---------|
| CYCLE81 | 快速定位 → 进给到孔底 → 快速返回 |
| CYCLE82 | 快速定位 → 进给到孔底 → 停顿 → 快速返回 |
| CYCLE83 | 快速定位 → 分段啄钻（每步 MDEP，退至清洁平面）→ 快速返回 |
| CYCLE84 | 快速定位 → 进给攻丝到底 → 反转退出 |
| CYCLE85 | 快速定位 → 进给铰孔到底 → 进给退出 |

### 4.2 渐进式参数展示

**基本模式（默认显示）**：
- 策略选择（自动推荐）
- 刀具选择（自动推荐直径）
- 主轴转速（已填默认值）
- 进给速度（已填默认值）
- 加工深度（从特征自动读取）

**高级模式（折叠展开）**：
- 安全高度、进给起始高度
- 每刀步距、停顿时间
- 余量、刀补方向
- 程序号、备注

### 4.3 典型操作流程（目标：≤ 8 步）

```
步骤 1  拖入/导入 STEP 文件
步骤 2  等待自动识别（< 5 秒），特征树展示识别结果
步骤 3  勾选目标孔（可多选）
步骤 4  系统自动推荐策略和刀具，显示在策略面板
步骤 5  （可选）修改转速/进给等参数
步骤 6  点击「生成G代码」
步骤 7  三维视口显示刀路，G代码编辑器显示代码
步骤 8  点击「导出」，保存 .mpf 文件
```

## 6. 关键技术决策

### 6.1 为什么不依赖外部 CAM 库

代码完全闭环是核心约束。依赖 OpenCAMLib 等库会引入：
- 授权和分发风险
- 依赖版本锁定问题
- 算法黑盒难以调试和针对性优化

所有刀路算法（行切、圆插补、轮廓偏置、等高线）均在项目内自行实现。

### 6.2 中间 G 代码格式（;CNEXT_HOLE_CYCLE）

将策略与后处理器解耦：
- 策略不关心目标控制器，只输出几何参数
- 后处理器不关心加工工艺，只做语法转换
- 未来新增控制器只需新增后处理器，策略代码无需修改

### 6.3 AAG 邻接属性图

基于面法向和边切向判断凹凸边，避免依赖 STEP 几何内核的 B-Rep 拓扑 API：
- 输入：三角面网格（OCC 三角化后导出）
- 输出：面-边邻接关系 + 凹/凸/平滑 边属性
- 优点：对 STEP 三角化精度不敏感，适合各种来源的 STEP 文件

## 7. 构建与部署

### 7.1 构建命令

```bash
qmake untitled.pro
mingw32-make -f Makefile.Debug
```

### 7.2 运行依赖（已打包到 Debug 目录）

- Qt5Core / Qt5Gui / Qt5Widgets / Qt5OpenGL
- OpenCASCADE（TKSTEP / TKBRep / TKMesh / TKIGES 等）
- MSYS2 运行时（libstdc++, libgcc, libwinpthread）
- 软件渲染模式：启动时设置 `Qt::AA_UseSoftwareOpenGL`

### 7.3 分发目标

单目录绿色分发包，双击 EXE 直接运行，无需安装 CNC 软件或 Qt 开发环境。
