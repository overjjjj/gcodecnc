### P11 修复：槽方向角未提取，G 代码始终按 0° 生成槽路径

**问题现象**：识别到的槽特征（`MachiningFeature`）没有方向角字段，`MillingOperationDialog` 中 `"angle"` 参数始终使用策略默认值（0°），G 代码对旋转槽路径错误。

**根本原因**：
1. `MachiningFeature` 缺少 `angle` 字段。
2. `estimatePlanarFaceBox` 用固定世界坐标轴（u/v）计算包围盒，只能给出轴对齐尺寸，无法提取槽的实际长轴方向。
3. 即使识别器计算出角度，也没有路径把它传入工序对话框的参数表。

**修复（三步）**：

**步骤1** — `StepImporter.h`：在 `MachiningFeature` 中增加字段：
```cpp
double angle = 0.0;  // slot/feature orientation in XY plane (degrees, 0=X axis)
```

**步骤2** — `FeatureRecognizer.cpp`：
- `FaceBox2D` 增加 `double angle = 0.0;` 字段。
- `estimatePlanarFaceBox` 函数末尾增加 PCA（主成分分析）：对槽底面所有网格节点在 XY 平面投影，构建 2×2 协方差矩阵，解析求最大特征值对应的特征向量，用 `atan2` 转为角度存入 `box.angle`。用 `std::acos(-1.0)` 替代 `M_PI` 以保证 MSVC 可移植性。
- `findSlots()` 中赋值 `feature.angle = box.angle;`。

**步骤3** — `MillingOperationDialog.cpp`：在 `setFeature()` Slot 分支的参数覆写循环中，新增对 `"angle"` 键的处理：
```cpp
} else if (key == QStringLiteral("angle")) {
    valueItem->setText(QString::number(feature.angle, 'f', 2));
}
```

**改动文件**：
- `src/import/StepImporter.h`（MachiningFeature 新增 angle 字段）
- `src/import/FeatureRecognizer.cpp`（FaceBox2D + estimatePlanarFaceBox + findSlots）
- `src/ui/MillingOperationDialog.cpp`（setFeature 参数覆写循环）

### P7 修复（第五轮）：弧端槽底面被误过滤 + 外表面被误纳入槽高亮

**修复 1 — 外表面被纳入槽高亮（四面槽问题，延续 P5）**

**根本原因**：`estimatePlanarDepthFromSides` 使用 `std::abs()` 计算侧面邻居与底面的距离差，导致在底面法向反方向的大外部平面（工件顶面的反面）同样被计为有效深度，通过了深度 ≥ 0.5 mm 的过滤。

**修复**：改为有符号方向计算：
```cpp
const double delta = QVector3D::dotProduct(c, n) - bottomProj;
if (delta > 0.0) maxDelta = std::max(maxDelta, delta);
```
只统计严格位于底面法向正方向（即槽上方）的邻居，外部面深度返回 0，被过滤。

**改动文件**：`src/import/FeatureRecognizer.cpp` — `estimatePlanarDepthFromSides`（约第 501 行）

---

**修复 2 — 弧端槽（arc_slot）底面被 `isReasonableRecessBottom` 误过滤**

**根本原因**：`isReasonableRecessBottom` 调用 `countFaceWires(face) > 1` 过滤带多个 wire 的底面，初衷是排除带内孔的大顶面。但弧端槽在 STEP 格式中，底面可能拆成多个外轮廓 wire（弧段 + 直线段各一条），同样会被 `> 1` 误过滤，导致弧端槽底面无法被识别。

**修复**：删除 `countFaceWires()` 函数，替换为 `faceHasInnerWires()`：
```cpp
static bool faceHasInnerWires(const TopoDS_Face &face)
{
    // 内 wire（孔洞）在 OCC 中相对 face 方向为 TopAbs_REVERSED；
    // 外轮廓（含被 STEP 拆分的多段弧）均为 FORWARD，不应过滤。
    for (TopExp_Explorer explorer(face, TopAbs_WIRE); explorer.More(); explorer.Next()) {
        const TopoDS_Shape &wire = explorer.Current();
        if (wire.Orientation() == TopAbs_REVERSED)
            return true;
    }
    return false;
}
```
调用处改为 `if (faceHasInnerWires(face)) return false;`，正确区分真内孔 wire（REVERSED）和弧端外轮廓分段 wire（FORWARD）。

**改动文件**：`src/import/FeatureRecognizer.cpp` — 函数 `countFaceWires`（删除）→ `faceHasInnerWires`（新增），及 `isReasonableRecessBottom`（约第 304 行）调用更新。

### P8 修复（第六轮）：相邻两槽跨槽面污染（第二个槽识别混入第一个槽的侧壁）

**问题现象**：识别两个相邻槽时，第一个槽四面全部正确；第二个槽被识别成第一个槽的两个侧壁 + 工件外表面的混合，而非第二个槽自身的四个面。

**根本原因**：`findSlots` 每次迭代候选底面时，从 AAG 邻居中收集凹边邻居为侧面，但没有全局记录已属于确认槽的面。第一个槽确认后，其侧壁仍可作为第二个候选底面的 AAG 凹边邻居被重复采用，导致跨槽面污染。

**修复**：在 `findSlots` 函数内部增加 `QSet<int> consumedFaces`，记录已被确认槽占用的底面和侧面：
1. 循环开头：若 `faceIndex` 已在 `consumedFaces` 中则跳过；
2. 收集侧面时：过滤掉 `consumedFaces` 中已有的邻居，避免重复纳入；
3. 槽被接受后：将底面 + 所有侧面批量插入 `consumedFaces`。

```cpp
// findSlots 顶部
QSet<int> consumedFaces;

// 循环开头
if (consumedFaces.contains(faceIndex)) continue;

// 收集侧面时
if (!consumedFaces.contains(neighborIndex))
    sideFaces.append(neighborIndex);

// 槽接受后
consumedFaces.insert(faceIndex);
for (int sideIndex : sideFaces) consumedFaces.insert(sideIndex);
```

**改动文件**：`src/import/FeatureRecognizer.cpp` — `findSlots()`（约第 992 行）

已通过 `mingw32-make -f Makefile.Debug debug/FeatureRecognizer.o` 编译验证（无错误），待完整链接后运行时测试。

### P5 修复（第三轮）：槽/型腔把外表面整个识别进去的问题

**根本原因**：`findSlots()` 和 `findPockets()` 没有校验底面是否真正凹陷于侧面之下。外层顶平面（工件顶面）因与槽壁共享凹边，且 `isReasonableRecessBottom` 的底/侧比检查在槽较长时通过，导致顶面被误识别为槽底并把所有侧面纳入 `faceIndices`。

**修复方法**：在 `isReasonableRecessBottom` 过滤之后，提前调用 `estimatePlanarDepthFromSides`，若返回深度 < 0.5 mm 则跳过。这确保识别到的底面必须在侧面下方至少 0.5 mm（即槽/腔确实存在），外层顶面因找不到更高的同向平面邻居、深度为 0，被过滤掉。

**改动文件（1 处）**：

`src/import/FeatureRecognizer.cpp`
- `findSlots()`（约第 1058 行后）：在建立 `MachiningFeature` 之前加 `depth < 0.5 → continue` 判断，并复用该 `depth` 值赋给 `feature.depth`（消除重复计算）
- `findPockets()`（约第 1161 行后）：同上逻辑，同时将原重复的 `double depth = estimatePlanarDepthFromSides(...)` 合并为一次调用

### P4 修复（第二轮）：曲面侧面被误识别为槽/型腔的问题

**根本原因**：
1. `findSlots()` 第一轮修复只检查了圆柱邻居的轴线方向，**未检查平面邻居的法向量**。平面型壁面必须与底面法向垂直（`|dot| ≤ 0.3`），否则倾斜面、台阶面会被误纳入。
2. `findPockets()` 完全没有方向检查，圆柱和平面邻居一律接受。

**改动文件（1 处）**：
