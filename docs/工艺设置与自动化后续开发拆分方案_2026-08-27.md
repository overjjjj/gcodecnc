# 工艺设置与自动化后续开发拆分方案（2026-08-27）

## 依据、估算口径与边界

依据为第七章说明书、现有截图/DTM 交付包、已归档的 DTM 资料、五份自动化模板的只读提取结论、当前收口清单和自动化模板映射。`docs/设计界面功能实现状态与后续开发方案_2026-08-27.md` 当前工作树不存在，本方案不假定其内容。

- **团队基准：** 4 名 C++/Qt 开发加 1 名 CNC/测试集成人员，2 周一个迭代。估算以已完成的安全子集为起点，不重复计算已落地的参数 schema、候选确认、二维内核和当前已验证策略。
- **估算口径：** 人周是实际工程投入；日历周包含依赖、评审、机床/后处理器可用性和集成等待。以下是保守计划估算，不是交付承诺。
- **版本切分：** V1 内部试用只承诺可审计的资料、候选、确认、最终代码与回归；V1.0 生产验收补足控制器/机床夹具和发布证据；动态铣、凹多边形/复杂偏置、复杂 3D 曲面、插角不属于 V1。
- **风险缓冲：** 基线工作量为约 52–70 人周；加入 20%–30% 缓冲后，V1.0 计划容量为约 64–91 人周。

| 配置 | V1 内部试用 | V1.0 生产验收 | 说明 |
| --- | --- | --- | --- |
| 4+1 基准团队 | 10–12 日历周 | 14–18 日历周 | 推荐；测试集成人员全程参与。 |
| 2 人 | 16–22 周 | 20–28 周 | 共享边界和机床验证成为串行瓶颈。 |
| 3 人 | 12–17 周 | 15–22 周 | 可并行规则与 UI，但集成仍受限。 |
| 6 人 | 8–12 周 | 10–16 周 | 不按人数线性缩短，需严格接口冻结。 |

高级动态铣和复杂 3D 在生产 V1 后另行估算 12–20 周，且需要专职 CAM 几何/算法人员和代表性机床验证，不纳入上述 V1 承诺。

### 统一完成定义（DoD）

每个模块的 DoD 为：参数/接口文档完成；先有失败的单元或合同测试；不越过公开边界；候选必须保留拒绝原因；确认通过 `OperationFactory` 原子创建；受影响路径具有 CQ8/Fanuc/Siemens（适用时）最终代码、安全校验和最终代码仿真；保存重开与失效规则覆盖；`git diff --check`、聚焦测试和 Debug 构建通过。无法证明几何或机床安全时，交付明确拒绝而非假实现。

每个模块的回退是关闭该规则/JSON 版本的匹配或禁用候选入口，保留已确认工序快照；不得通过回写或删除工序回退。

## 架构冻结与冲突治理

- 模块不得直接写正式 `MachiningOperation`、绕过人工确认或 `OperationFactory`、直接拼接 Fanuc/CQ8/Siemens 文本，或修改其他模块私有结构。
- `ProcessTemplateLibrary` 和 M0 JSON 是资料边界；规则层只产出 `Operation Proposal`；策略只输出 `Toolpath Result`；后处理与仿真保持最终代码边界。
- `untitled/untitled.pro`、`untitled/scripts/run_tests.ps1`、`untitled/src/core/ProjectManager.*`、`untitled/src/strategies/StrategyFactory.cpp`、`untitled/src/core/ProcessParameterSchema.*`、`untitled/src/services/ProgramGenerationService.*`、`untitled/src/gcode/GCodeSafetyValidator.*`、`untitled/src/postprocessor/**` 为高冲突文件：仅集成人维护，开发者需先预约变更并提供最小 patch。
- 冷却相关代码和行为继续冻结；即使资料含冷却枚举，也只能作为兼容字段，不得实现或修改输出，除非另立需求并完成单独 CNC 安全审查。

## 依赖图、并行与六迭代计划

文字依赖图：`M0 → M1 → {M2, M3, M4}`；`M2 → M5`；`{M2, M3, M4, M5} → M7 → M8`；`M6` 从 M0 开始并随 M2–M5 分阶段接入；`M9` 仅在 M3/M5 有证明的几何阻塞时插入。关键路径为 `M0 → M2/M3/M4/M5 → M7 → M8`。

| --- | --- | --- |

| I4 | M2/M3 确认链、M4 可验证子集、M5 规格候选 | M6 接入已冻结服务；M9 仅处理明确阻塞。 |
| I5 | M7 控制器/仿真回归、M6 管理 UI、M8 发布证据 | 设计评审决定 V1 feature freeze；禁止新增高级算法。 |

M2、M3、M4 可并行；M6 可在 M0 后并行开发只读部分；M7/M8 可提前准备夹具但不能替代确认后的最终代码验收。M0、共享 DTO 冻结、`OperationFactory` 确认语义、最终后处理合同不可并行随意变更。

节奏：I1/I2 各一次接口冻结会；每个迭代开始做设计评审、每周集成人审核共享文件预约和 cherry-pick 队列、每个迭代结束运行构建/聚焦测试/最终代码回归并更新风险表。

## 工期结论

建议采用 4+1 团队 **V1 内部试用 10–12 周、V1.0 生产验收 14–18 周**。该区间与 64–91 人周的含缓冲容量一致，并为机床、控制器和验收 STEP 夹具的不确定性保留空间。2 人采用 20–28 周，3 人采用 15–22 周，6 人采用 10–16 周；6 人的缩短上限受高冲突共享边界和 CNC 验证序列限制。

V1 的发布门必须包含稳定测试模型、可确认候选、最终 CQ8/Fanuc/Siemens（适用场景）代码、`GCodeSafetyValidator`、最终代码仿真和机床/后处理器签字。当前 `acceptance_step_model_test` 的侧面型腔专用 Setup 缺失单列为基线问题，不得通过放宽 Setup 安全门解决。

## Git 与集成方案

- 每个模块使用独立 `codex/<module>-...` 分支或工作树；模块分支之间不互相 merge。
- 使用 Conventional Commits，小批提交，明确路径暂存；禁止 `git add -A`、`git add .` 和提交构建产物。
- 集成人在集成分支按依赖顺序 cherry-pick 或 merge，先 M0，再 M1/M2/M3/M4/M5，后 M6/M7/M8；M9 只按已批准的阻塞项进入。
- 每次合入必须检查缓存范围、`git diff --cached --check`、Debug 构建、聚焦测试；涉及路径时增加最终 G-code 安全检查和仿真证据。
- `acceptance_step_model_test` 的专用 Setup 问题独立跟踪；不得跳过、删除或放宽安全校验。
