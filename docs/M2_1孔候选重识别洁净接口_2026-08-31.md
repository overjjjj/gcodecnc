# M2.1 孔候选重识别与人工覆盖洁净接口（2026-08-31）

## 1. 目的、范围与证据

本文为 M2 的候选重识别、人工覆盖和沉头取消收敛一份可编码的领域合同。它只消费已提交的 DTM 洁净规格、M2 接口/黑盒规格以及项目公开领域接口。

- 服务输入为当前不可变孔快照及可选的 `previousCandidate` 快照；输出只为候选状态、差异解释和稳定原因，绝不创建正式工序。
- 不接 UI、`OperationFactory`、刀路、后处理、控制器、G-code、安全校验、仿真或冷却；不修改其中任何行为。
- 所有“相同”比较使用版本化 DTO 已提供的稳定标识作精确比较；本合同不以名称、显示文本、列表顺序、当前最新版本或近似尺寸推断相同。
- 沿用上位洁净规格的证据分类；其中 `推断` 是可评审合同，不是已确认的业务事实。

本文不取代 M2 的规则匹配、表达式、刀具可行性或人工确认合同；只规定它们在重识别时如何产生可解释的候选状态。

## 2. 统一术语

| 术语 | 唯一定义 | 不等同于 |
| --- | --- | --- |
| 候选快照 | 某次识别与匹配结果的不可变、可比较记录。 | 可写的 UI 编辑模型或正式工序。 |
| 当前观测 | 本次识别、匹配和资料解析取得的不可变输入。 | 对旧候选的就地更新。 |
| 身份维度 | `geometryRef`、`geometryRevision`、`layerSignature` 和全部被引用资料版本。 | 显示名称、更新时间或规则行序。 |
| 同一几何 | `geometryRef`、`geometryRevision`、`layerSignature` 三者均精确相同。 | 仅 `geometryRef` 相同。 |
| 同一可复用方案 | 同一几何，且规则、计划、模板、材料、机床和刀具目录版本均精确相同。 | 有相似步骤或同名方案。 |
| 人工覆盖 | 操作者明确保存的进给、转速、刀具或方案选择；每项须定位到稳定目标。 | 匹配服务猜测的默认参数。 |
| 保留 | 在同一可复用方案上原样携带一个可定位且仍可解析的人工覆盖。 | 静默重算、换刀或改值。 |
| 冲突 | 输入/资料仍可解析，但旧快照与当前观测或人工覆盖不兼容，须人工处理。 | 可由服务选择一方解决的普通差异。 |
| 过期 | 比较所需的旧引用版本、旧几何或资料目录无法解析。 | 有一个更新版本可用。 |

`M21-IF-TERM-001` “取消沉头”是针对候选计划中 `countersinkStep=true` 的显式人工覆盖，不是改变孔层几何或对所有外层步骤的泛化删除。`[上位规范：M2-IF-STATE-005、DTM-CLN-HOLE-006；证据类型：说明书 + Excel + 推断]`

## 3. 不可变输入与最小 DTO

| --- | --- | --- | --- | --- |
| `requestId` | stable string | 是 | 单次调和追踪 ID；不参与相同判定。 | `M2-IF-INPUT-002`、`DTM-CLN-COMMON-003` / 推断 |
| `observedCandidate` | `ObservedCandidateSnapshot` | 是 | 本次识别和匹配得到的只读候选观测。 | `M2-IF-OUTPUT-001` / 说明书 + 推断 |
| `previousCandidate` | optional `PreviousCandidateSnapshot` | 否 | 仅作为比较基线；不存在时不发生“保留”。 | `M2-IF-INPUT-001`、`M2-IF-STATE-001` / 说明书 + 推断 |

### 3.3 `ObservedCandidateSnapshot`

`ObservedCandidateSnapshot` 是本次 M2 匹配的不可变输出副本；不是旧候选的可写替身。它的 `state` 只允许 `Draft`、`Conflict` 或 `Rejected`：当前匹配的 `Stale` 必须先作为不可解析的当前输入被 M2 拒绝，不可伪装为可调和候选。

| 字段 | 类型 | 必填 | 合同 | 上位规范 / 证据类型 |
| --- | --- | --- | --- | --- |
| `observedCandidateId` / `observedRevision` | stable strings | 是 | 当前观测的稳定身份；不可重用旧 `snapshotRevision`。 | `M21-IF-INPUT-001` / 推断 |
| `state` | `Draft` / `Conflict` / `Rejected` | 是 | `Draft` 才可进入旧候选比较；`Conflict` / `Rejected` 必须原样传播。 | `M2-IF-OUTPUT-001` / 说明书 + 推断 |
| `featureIdentity` | `FeatureIdentity` | 是 | 三个字段齐全；即使 `Conflict` / `Rejected` 也须保留已识别几何身份。 | `M21-IF-IDENTITY-001` / 说明书 + 推断 |
| `provenance` | `CandidateProvenance` | 仅 `Draft` | `Draft` 必填且完整；`Conflict` / `Rejected` 必须为 null，避免制造并不存在的胜出方案。 | `M2-IF-OUTPUT-001` / 推断 |
| `effectivePlan` | immutable normalized steps | 仅 `Draft` | `Draft` 必填且至少一个步骤；`Conflict` / `Rejected` 必须为空。 | `M2-IF-STEP-001`、`M2-IF-OUTPUT-001` / Excel + 推断 |
| `matchExplanation` | structured explanation | 是 | `Conflict` 必须包含顶级规则冲突；`Rejected` 必须包含匹配/输入拒绝原因；`Draft` 包含唯一胜出依据。 | `M2-IF-OUTPUT-001`、`M2-IF-RULE-003` / 说明书 + Excel + 推断 |
| `reasons` | stable reason list | 条件必填 | `Conflict` / `Rejected` 非空，`Draft` 为空。 | `M2-IF-OUTPUT-001` / 说明书 + 推断 |

`M21-IF-OBSERVED-001` 当 `observedCandidate.state=Conflict` 或 `Rejected` 时，M2.1 在快照结构和调和政策校验后立即传播该状态及其 `reasons`，不比较 `previousCandidate`，不解析旧引用，也不声称保留人工覆盖。结果 `candidate=null`，`manualEditDisposition=None`。`[上位规范：M2-IF-OUTPUT-001、M2-IF-RULE-003；证据类型：说明书 + Excel + 推断]`

### 3.4 `ResolutionView`

`resolutionView.entries` 是无序集合；每个条目用 `(side, referencePath, referenceIdentity)` 组成唯一键。`side` 只可为 `Previous`、`Observed` 或 `Request`；`Request` 只用于 `reconciliationPolicyVersion`。

| 字段 | 类型 | 必填 | 合同 | 上位规范 / 证据类型 |
| --- | --- | --- | --- | --- |
| `side` | enum | 是 | `Previous` 覆盖旧候选所需引用，`Observed` 覆盖当前 `Draft` 所需引用，`Request` 覆盖政策引用。 | `M21-IF-STATE-001` / 推断 |
| `referencePath` | JSON Pointer string | 是 | 仅允许 `/featureIdentity/geometryRef`、`/featureIdentity/geometryRevision`、`/featureIdentity/layerSignature`、`/provenance/ruleRef`、`/provenance/planRef`、`/provenance/templateRef`、`/provenance/materialRef`、`/provenance/machineProfileRef`、`/provenance/toolCatalogRef` 或 `/reconciliationPolicyVersion`；必须定位到该侧快照实际字段。 | `M21-IF-EXPLAIN-001` / 推断 |
| `referenceIdentity` | typed stable reference | 是 | 精确复制该路径的引用身份；不可只给名称或最新版本。 | `M2-IF-INPUT-002` / 说明书 + Excel + 推断 |
| `status` | `Resolvable` / `Missing` / `Withdrawn` | 是 | `Resolvable` 表示精确身份已解析；`Missing`、`Withdrawn` 均不允许替换为另一版本。 | `M2-IF-STATE-003` / 说明书 + 推断 |

`M21-IF-RESOLUTION-001` 任意当前观测状态都必须恰有一条覆盖 `Request/reconciliationPolicyVersion` 的条目；在 `observedCandidate.state=Draft` 时，还必须恰有一条覆盖每条旧候选必需引用及每条当前 `Draft` 必需引用。缺条目、键重复、路径不允许、条目身份与字段不精确相等或 `Resolvable` 身份不一致，均为 `Rejected/RESOLUTION_VIEW_INVALID`；此结构错误优先于 `Stale` 和比较。`[上位规范：M2-IF-INPUT-002、M2-IF-STATE-003；证据类型：说明书 + 推断]`

`M21-IF-RESOLUTION-002` 在有效 `resolutionView` 中，`Request` 政策条目非 `Resolvable` 时返回 `Rejected/RECONCILIATION_POLICY_UNRESOLVED`；旧候选任一必需引用为 `Missing` 或 `Withdrawn` 时返回 `Stale/CANDIDATE_REFERENCE_UNRESOLVED`；当前 `Draft` 任一必需引用非 `Resolvable` 时返回 `Rejected/CANDIDATE_SNAPSHOT_INVALID`。这些结果都不寻找或使用当前最新版本。`[上位规范：M2-IF-STATE-003、M2-BB-024、M2-BB-030；证据类型：说明书 + 推断]`

## 4. 比较、解析与状态机

### 4.1 判定顺序

1. 校验请求、旧快照（如有）和当前观测的必填字段、允许状态、条件字段；再校验 `resolutionView` 键的唯一性、路径、身份和覆盖范围。任一结构错误均为 `Rejected`，且优先于所有解析与比较。
2. 解析 `Request/reconciliationPolicyVersion`；不可解析时为 `Rejected/RECONCILIATION_POLICY_UNRESOLVED`，优先于旧引用状态。
3. 若当前观测为 `Conflict` 或 `Rejected`，按 `M21-IF-OBSERVED-001` 原样传播并结束；不存在旧候选比较或恢复。
4. 当前观测为 `Draft` 时，解析旧候选和当前观测的必需引用。旧任一引用 `Missing` / `Withdrawn` 为 `Stale`；当前任一引用非 `Resolvable` 为 `Rejected`。两者均不寻找替代版本。
5. 无 `previousCandidate` 时，返回当前 `Draft`，不声称人工覆盖被保留。
6. 比较几何三元组；任一差异为 `Conflict`。
7. 比较全部资料版本；任一可解析差异为 `Conflict`。
8. 在同一可复用方案上，逐项验证人工覆盖目标与刀具选择；无法保留者为 `Conflict`，其余明确为 `Preserved`。
9. 处理 `cancelCountersink`；只按有效计划步骤的布尔标志过滤，并对剩余链完成 M2 已有校验。
10. 仅当所有必要比较相同且有效覆盖均已保留时，返回旧的可编辑状态；普通旧态直接保留 `Draft` / `Selected`，旧态为 `Stale` 时严格按 `lastEditableState` 恢复。没有人工覆盖时处置为 `None`。

`M21-IF-STATE-001` 判定优先级为“快照/解析视图结构错误 → 政策不可解析 → 当前 `Conflict`/`Rejected` 传播 → 旧/当前引用解析 → 几何差异 → 来源差异 → 覆盖/沉头校验 → 保留或恢复”。因此旧引用不可解析优先于几何/来源差异（`Stale`），而政策不可解析和解析视图缺项优先于 `Stale`（`Rejected`）。`[上位规范：M2-IF-STATE-003、M2-BB-024、M2-BB-028、M2-BB-030；证据类型：说明书 + 推断]`

`M21-IF-STATE-002` 解析成功后的不一致优先于保留：几何、方案或任何资料版本改变，以及覆盖目标失效，均为 `Conflict`；`Conflict` 不清除旧候选、覆盖、选择或取消标志。`[上位规范：M2-IF-STATE-002、M2-IF-STATE-004、M2-BB-027、M2-BB-029、M2-BB-042；证据类型：说明书 + Excel + 推断]`

### 4.2 可观察状态机

```text
无 previousCandidate ──────→ Draft / Rejected / Conflict（采用当前观测）

Draft 或 Selected
  ├─ 比较引用不可解析 ────→ Stale
  ├─ 几何或可解析资料变化 ─→ Conflict
  ├─ 同一方案、覆盖可定位 ─→ 原状态 + Preserved
  └─ 取消沉头后空链 ──────→ Rejected

Conflict ──独立授权的人工重处理命令────→ Draft 或 Selected（M2.1 外部）
Stale    ──旧引用重新可解析且重评估通过──→ lastEditableState（Draft 或 Selected）
Rejected ──新的完整有效观测──────────────→ Draft
```

`M21-IF-STATE-003` `Selected` 仅表示候选内已显式选择方案；M2.1 既不验证确认事务，也不转换为 `Validated` 或 `Confirmed`。`[上位规范：M2-IF-STATE-001、M2-IF-OUTPUT-002；证据类型：说明书 + 推断]`

`M21-IF-STATE-004` 对无人工覆盖的 `Draft`，同一可复用方案重识别保持 `Draft`、`manualEditDisposition=None`；不得伪称 `Preserved`。`[上位规范：M2-IF-STATE-001、M2-BB-026；证据类型：推断]`

`M21-IF-STATE-005` 恢复 `Stale` 候选时，只有在所有引用重新 `Resolvable`、当前观测为 `Draft`、几何/来源完全相同且覆盖/取消沉头校验通过后，才以 `lastEditableState` 输出；`Selected` 恢复必须带回原 `selectedPlanRef`。这些条件任一不满足时继续按既有优先级输出 `Stale`、`Conflict` 或 `Rejected`。`[上位规范：M21-IF-RECOVERY-001、M2-BB-030；证据类型：推断]`

## 5. 取消沉头合同

`M21-IF-CANCEL-001` `cancelCountersink=true` 只移除当前有效计划中 `countersinkStep=true` 的步骤；不得改变剩余步骤的 `stepId`、顺序、层引用、深度表达式、进给、转速或刀具选择。`[上位规范：M2-IF-STATE-005、M2-BB-013；证据类型：说明书 + Excel + 推断]`

`M21-IF-CANCEL-002` 过滤后无步骤时返回 `Rejected / CANDIDATE_STEP_CHAIN_EMPTY`，差异解释必须包含被过滤步骤；不产生空 `Draft` 或正式工序。`[上位规范：M2-BB-014、DTM-CLN-HOLE-004、DTM-CLN-HOLE-006；证据类型：Excel + 推断]`

`M21-IF-CANCEL-003` 旧候选取消过沉头时，只有同一几何且同一可复用方案才可保留该标志；沉头层、计划版本或 `countersinkStep` 分配变化且仍可解析时为 `Conflict`，不得悄然清除或迁移该标志。`[上位规范：M2-IF-STATE-005、M2-BB-041、M2-BB-042；证据类型：说明书 + Excel + 推断]`

## 6. 输出、错误和差异解释

### 6.1 `CandidateReconciliationResult`

| 字段 | 类型 | 合同 | 上位规范 / 证据类型 |
| --- | --- | --- | --- |
| `state` | `Draft` / `Selected` / `Conflict` / `Stale` / `Rejected` | 候选状态；不含正式工序状态。 | `M21-IF-STATE-003` / 说明书 + 推断 |
| `candidate` | immutable reconciled snapshot / optional | `Draft`/`Selected` 为新快照：以当前 `Draft` 观测为内容，仅复制经验证可保留的人工项。`Conflict`/`Stale` 且有旧候选时为新快照：除结果 `state`、新 `snapshotRevision` 和调和元数据外，业务内容精确复制旧候选，当前观测只出现在 `explanation` 中；不得混合两侧字段。无旧候选的当前 `Conflict` / `Rejected` 及所有 `Rejected` 结果为 null。 | `DTM-CLN-COMMON-003`、`DTM-CLN-COMMON-004` / 说明书 + 推断 |
| `manualEditDisposition` | `None` / `Preserved` / `Conflict` / `Stale` | 对人工覆盖的整体可观察结论；无覆盖不得为 `Preserved`。 | `M2-IF-OUTPUT-001`、`M21-IF-STATE-004` / 说明书 + 推断 |
| `differences` | non-empty list on `Conflict`/`Stale` | 每项含 `kind`、旧值引用、当前值引用（如可得）、稳定错误码和字段路径。 | `M2-IF-OUTPUT-001` / 推断 |
| `reasons` | non-empty list on `Rejected` | 每项含稳定错误码和字段路径。 | `M2-IF-OUTPUT-001` / 推断 |
| `explanation` | structured object | 记录比较顺序、引用解析结果、保留/冲突覆盖及沉头过滤结果。 | `M2-IF-OUTPUT-001` / 推断 |

### 6.2 稳定错误码与路径

| 错误码 | 触发 | 最小字段路径 | 上位规范 / 证据类型 |
| --- | --- | --- | --- |

| `RECONCILIATION_POLICY_UNRESOLVED` | 调和合同版本缺失或不可解析 | `reconciliationPolicyVersion` | `DTM-CLN-COMMON-007` / 推断 |

| `CANDIDATE_PROVENANCE_CHANGED` | 任一可解析资料版本差异 | `provenance.<ref>` | `M21-IF-IDENTITY-002` / 说明书 + 推断 |

`M21-IF-EXPLAIN-001` 每个 `Conflict`、`Stale` 或 `Rejected` 必须附 `requestId`、`candidateId`（如有）、状态、错误码、JSON Pointer 风格字段路径和安全的旧/当前引用；不得泄露 UI 状态、内部实现信息或控制器文本。`[上位规范：M2-IF-OUTPUT-001、DTM-CLN-COMMON-003；证据类型：说明书 + 推断]`

`M21-IF-OUTPUT-001` 任何结果都不得就地修改 `previousCandidate` 或 `observedCandidate`。输出快照必须有新的 `snapshotRevision`、`baseSnapshotRef` 和 `observationRef`；`Conflict`/`Stale` 的有效计划、人工覆盖、取消沉头和已选方案只能来自旧候选的完整复制，差异只记录在 `differences/explanation`。`[上位规范：M21-IF-INPUT-001、M21-IF-STATE-002；证据类型：说明书 + 推断]`

## 7. 明确阻断项

下列问题在现有证据中不能唯一确定；相应功能必须阻断，不能由 M2.1 补默认：

| 阻断项 | 未确认前要求 | 证据类型 |
| --- | --- | --- |
| `layerSignature` 的跨序列化规范、哈希算法与兼容版本 | 仅比较上游已提供的稳定值；缺失或不同格式不作语义归一化，返回 `Rejected/CANDIDATE_SNAPSHOT_INVALID` 或由上游拒绝。 | 推断 |
| 刀具 selector 的等价关系 | 不把同名、同直径或相似刀具视为同一把；需要唯一版本引用，否则 `Conflict`。 | 说明书 + Excel + 推断 |
| 人工进给/转速覆盖与新方案步骤的迁移规则 | 不跨 `stepId`、策略或方案版本迁移；目标不存在即 `Conflict`。 | 推断 |
| 重识别对已 `Conflict`/`Stale` 覆盖的“人工重新处理”动作语义 | M2.1 只报告状态；如何写入新快照需独立业务命令合同。 | 推断 |
| 从 `Conflict`/`Stale` 到可编辑态的授权、审计和事务 | 不接 UI 或确认事务；需业务批准的命令/审计模型。 | 推断 |
| 任何创建/回滚正式工序的事务语义 | M2.1 不调用 `OperationFactory`；维持 M2 原子确认边界。 | 说明书 + 推断 |

`M21-IF-BLOCK-001` 阻断项存在时服务只能输出稳定拒绝或冲突/过期解释，不能通过自动 selector 选择、参数迁移、版本替换、空步骤补齐或事务猜测得到可确认候选。`[上位规范：M2-IF-BOUNDARY-001、M2-IF-OUTPUT-002；证据类型：说明书 + 推断]`

## 8. 公共边界与禁止事项

| 公共边界 | M2.1 可做 | M2.1 禁止做 |
| --- | --- | --- |
| M0 版本化 DTO | 读取稳定身份、资料版本和解析结果。 | 读取 Excel、推断最新版本或改写 catalog。 |

| `OperationFactory` | 仅在说明中标注其处于人工确认边界之外。 | 调用、创建、删除或回滚正式工序。 |
| UI、策略、刀路、后处理、控制器、冷却 | 无。 | 直接依赖、修改或产生任何副作用。 |

`M21-IF-BOUNDARY-001` M2.1 完成定义是“把当前观测与旧候选确定性调和为可解释的候选状态”，不是自动确认、自动换刀、自动迁移人工参数或生成加工结果。`[上位规范：DTM-CLN-COMMON-003、DTM-CLN-COMMON-004、M2-IF-OUTPUT-002；证据类型：说明书 + 推断]`
