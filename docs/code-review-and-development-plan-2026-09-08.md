## 已核实问题

### R1 · P1：同刀号修改刀具尺寸，旧程序不会失效

- 位置：`untitled/src/workspaces/program_verification/fingerprint/ProgramSnapshotFingerprint.cpp:139`；`untitled/src/app/MainWindow.cpp:3514`、`:2877`。
- 触发：使用 T1、直径 6 生成槽或型腔程序，再将刀具库中同一个 T1 改为直径 10，然后导出原程序。
- 证据：工序指纹只保存 `toolId`，没有刀具实体或加工属性版本；刀库变更的窗口回调只保存 tools.json。生成服务却在 `ProgramGenerationService.cpp:550` 读取当前刀具实体。
- 影响：旧刀心轨迹仍被视为 Fresh，无法保证它与当前刀具一致。仿真读取当前刀库也会与生成时依据不同。
- 修复：快照保存所引用刀具的加工属性摘要或版本；刀库修改、删除应使受影响工序和程序失效，并更新输出按钮。未使用刀具的变更不应误伤无关程序。
- 验收：同 ID 改刀径、刀型或删除刀具均阻断旧程序输出；改无关刀具不影响；保存重开后仍能检测差异；重新生成后恢复。

### R2 · P1：快速移动只检查终点 Z，放行从切削深度斜向抬刀

- 位置：`untitled/src/workspaces/program_verification/safety/GCodeSafetyValidator.cpp:321`；`untitled/tests/gcode_safety_validator_test.cpp:99`。
- 示例：`G1 Z-1.000 F100` 后执行 `G0 X10.000 Y0.000 Z50.000`。
- 证据：检查使用目标 Z=50，没有要求 XY 快移开始前已经到安全高度。现有测试明确断言该片段应通过，本次运行该测试也通过。
- 影响：安全终点不能证明快速移动的中间路径安全；该门禁无法保证先抬刀再横移。这里只证明校验缺口，不断言所有现有策略都生成此片段。
- 修复：含 XY 的快速移动同时检查起点高度及适用安全平面；从切削高度离开先完成独立 Z 抬刀。先纠正测试预期，再修生产逻辑。
- 验收：上述片段和未知起始 Z 被拒绝；先 `G0 Z50` 再 `G0 X10 Y0` 被接受；孔固定循环、槽/型腔最终代码回归不受误伤。

### R3 · P1：确认保存新几何，刀路有效性却用旧几何验证

- 位置：`untitled/src/app/MainWindow.cpp:4364`、`:4380`、`:4434`、`:4442`。
- 触发：公共选择中改变开放轮廓的边/顺序，或平面铣改用尺寸、高度不同的毛坯。
- 证据：最终几何写入 `oneProposal.contourFeature`，经工厂形成正式工序；后续 `s->generate()` 仍遍历原 `contourBatch`，成功后将所有新工序标记为刀路有效。
- 影响：有效状态没有验证用户最终确认的输入，可能提前接受实际不可加工的几何。正式程序生成还有校验，因此不把它夸大为必然导出错误刀路。
- 修复：对最终确认工序的实际几何、参数和刀具逐项计算，通过后才标有效并整批提交。
- 验收：构造“原几何可加工、最终几何不可加工”，整批零新增；毛坯和局部轮廓成功案例使用最终输入；测试执行真实确认/生成逻辑，不能只检查源码字符串。

### R4 · P2：公共选择的“加工侧”没有进入策略输入

- 位置：`untitled/src/workspaces/process_design/ui/SelectionChainDialog.cpp:76`；`untitled/src/app/MainWindow.cpp:4364`；`untitled/src/workspaces/process_design/ui/ContourMachiningChoice.cpp:74`。
- 证据：内侧/外侧选择只写入选择证据；策略目录没有读取 `machiningSide` 或 `selectionEvidence`。轮廓策略使用的是前一对话框设置的 `params["compensation"]`。
- 影响：保持其他输入相同，仅切换公共框的加工侧，不会改变实际加工侧；反向后的刀补语义也缺少一致性检查。
- 修复：明确内外侧、轮廓方向与 G41/G42 的转换和冲突规则；尚不支持的选择应禁用或拒绝，不接受后忽略。
- 验收：同轮廓的内/外侧和反向组合，对应正确刀心路径或明确拒绝；同时核对最终 G 代码。

### R5 · P2：CQ8 压缩主程序与展开仿真共用行号，定位错位

- 位置：`untitled/src/app/MainWindow.cpp:2794`、`:2798`、`:3561`、`:3582`；`untitled/src/workspaces/program_verification/simulation/SimulationController.cpp:108`。
- 证据：编辑器显示 `gcodeText`，仿真加载 `expandedGcodeText`，播放和点击定位直接互传行号，没有展开行到主程序调用行的转换。
- 影响：有宏压缩时，高亮可能指向无关行或消失，点击主程序也可能跳到错误动作。
- 修复：保存展开动作到主程序调用行的映射；或提供明确的展开代码视图，让仿真只与该视图关联。
- 验收：至少两处宏调用、宏前后普通运动和程序尾部，播放高亮及点击定位都与同一实际动作对应。

### R6 · P2：测试入口漏注册，并允许指定测试实际零执行

### R7 · P2：工序上移后，项目回写会清除选中行

- 位置：`untitled/src/workspaces/process_design/ui/OperationListPanel.cpp:471`、`:394`；`untitled/src/app/MainWindow.cpp:3587`、`:3633`；`untitled/src/core/ProjectManager.cpp:116`。
- 证据：面板上移后恢复选中行并发出编辑信号；项目更新再发信号，主窗口调用面板 `setOperations()`，清空重建表格，选中行丢失。
- 影响：选中工序后连续上移/下移被中断。这是既有同步问题，不归因于最新选择 UI 改动。
- 修复：按工序 ID 保留选择；随后在唯一状态源改造中消除重复回写。
- 验收：带真实项目与面板信号链连续移动、删除和刷新，选中项稳定且一次命令只产生一次业务变更。当前独立面板测试不足以覆盖该链路。
