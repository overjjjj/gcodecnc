# M0 洁净规格对齐验收（2026-08-28）

## 1. 范围与结论

本验收只依据以下洁净规格，对 M0 已实现的版本化 DTO、JSON 白名单、
校验和迁移拒绝进行对照：

- `docs/DTM工艺规划洁净规格_2026-08-28.md`
- `docs/DTM工艺规划证据追溯矩阵_2026-08-28.md`

没有读取或引用反编译源码、原始伪代码、Excel、二进制或外部实现代码。
36 个规范 ID 的对照结果为：已覆盖 5 项、部分覆盖 16 项、未覆盖 11 项、
因语义未确认而明确阻断 4 项。

对齐发现五组属于 M0 且无歧义的缺陷，并按 TDD 修复：

1. 直径区间缺少显式开闭端点，旧实现实际假定为闭区间；
2. 来源元数据缺少 `effectiveDate`；
3. 螺纹唯一键错误包含 `standard`，且美制曾使用推测的 `unified` 名称；
4. 没有控制器、后处理和仿真合同时仍可启用深孔回退；
5. 参考面和端点语义未确认时仍可启用位置相关深孔阶段。

修复只收紧资料 schema 和拒绝条件，不增加规则匹配、工序创建、刀路、
后处理、仿真或冷却行为。

## 2. 状态定义

- **已覆盖：** M0 DTO/JSON 已完整表达并在加载时执行本条资料层合同。
- **部分覆盖：** M0 已表达资料子集，但几何、匹配、候选或确认语义属于后续模块。
- **未覆盖：** 本条不在 M0 资料层范围，当前 DTO 不声称提供该能力。
- **因语义未确认而明确阻断：** 未获得权威语义或运行合同前，不接受启用或不允许后续模块据此规划。

## 4. 冻结 DTO 与 JSON v1 边界

本轮对齐后，以下 M0 资料边界可供后续模块只读使用：

- `AutomationTemplateDocument`：`schemaVersion == 1`、文档 ID/版本、来源类型、
  名称、修订、ISO `effectiveDate`、SHA-256 摘要及五类资料数组；
- `ToolCuttingParameterSet`：材料、刀具类型/名称、显式开闭直径区间、
  建议进给/转速/步距/余量和兼容冷却字段；
- `FeatureMatchingRule` / `DiameterBand`：孔/框通用类别、尺寸、显式开闭档位、
  开闭/贯穿条件，不包含匹配算法；
- `AutomationMachiningPlanStep`：稳定步骤 ID、白名单策略、刀具/参考刀具选择器、
  起点/深度受限表达式、兼容冷却、启用/unsupported 原因和能力开关；
- `DeepHoleStageParameters`：阶段资料字段；位置相关阶段、回退和无级变速当前
  只能保持关闭，否则资料加载失败；
- `ThreadSpecification`：`metric/imperial/american`、标准元数据、规格、底孔、
  螺距、牙径、候选刀具和 XY 粗精兼容字段；唯一键为制式加规格。

JSON 未知字段、缺单位、缺边界端点、未知版本、非法范围、非法表达式、
重复 ID、重叠档位和未开放能力均使整份文档加载失败，不做部分加载或迁移猜测。

## 6. M1 / M2 接口条件

### M1 刀具资料匹配

- 输入必须明确指定资料文档版本、材料、规范化刀具类型/名称和目标直径；
- 必须按 `minimumInclusive/maximumInclusive` 判断端点，禁止重新假定闭区间；
- 只允许唯一档位结果；无匹配、重叠/多匹配、占位材料和未确认哨兵均返回资料错误；
- 输出仅为建议值、资料引用和匹配解释，不能修改刀库或已确认工序；
- 确认时仍须用刀具快照复验类型、直径、螺距、刀角、刃长、总长、额定值和机床限制。

### M2 孔规则与多步骤计划

- 只能消费稳定 `FeatureMatchingRule` 和显式端点，不得从 Excel 风格文本推断边界；
- `Hn/Dn/Tn/AT` 必须使用现有已测复合孔语义；坐标合同和 AT 上限确认前不得通用化；
- 当前步骤 DTO 尚未冻结目标层索引、沉头标志、计划分组和最多 11 步限制，
  M2 必须先以独立 TDD 批次补齐公共合同，不能私有猜字段；
- 匹配只能输出候选或稳定拒绝；全部步骤预校验通过并由操作者明确确认后，
  才可经 `OperationFactory` 原子创建正式工序链；
- 插角、动态铣、3D、密封槽、斜轴、破孔/相交和不可验证圆锥继续阻断。
