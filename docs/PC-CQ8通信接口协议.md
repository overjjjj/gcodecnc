## 2. 协议目标

本协议用于在 PC 上位机和 CQ8 之间可靠传输：

- 连接、版本协商和设备身份；
- 加工任务和程序元数据；
- 完整 G 代码下载；
- 大程序 G 代码流式下发；
- 启动、保持、恢复、停止和复位请求；
- 接收、解析、执行和缓冲水位状态；
- 坐标、刀具、主轴、进给和机床状态；
- 报警、诊断和运行日志。

本协议不承担实时插补、伺服闭环或硬件安全链功能。网络通信异常时，CQ8 必须能够独立完成受控减速、保持或安全停止。

## 3. 已确认约束

1. PC 和 CQ8 使用有线以太网通信。
2. 第一阶段使用 TCP 长连接。
3. G 代码程序超过产品配置阈值，或无法完整存入 CQ8 时，使用预下载流式执行。
4. 产品默认将 10000 行作为流式模式初始触发条件之一，但最终判断还包括程序字节数、CQ8 可用容量和程序复杂度。
5. CQ8 分别维护未解析 G 代码接收环形缓冲区和已规划轨迹缓冲区。
6. PC 只能下发已经通过完整安全校验且程序哈希已经冻结的程序。
7. CQ8 不得依赖 Windows 或以太网提供实时运动确定性。
8. CQ8 作为 TCP 服务端监听可配置端口，PC 作为 TCP 客户端负责连接、重连和状态同步。
9. 第一阶段使用单个 TCP 长连接复用控制、状态、报警和 G 代码程序消息，不建立独立程序数据连接。
10. PC 端采用 CNEXT-CAM 与 CNC_SYSTEM 双进程架构，只有 CNC_SYSTEM 可以作为 TCP 客户端连接 CQ8 并持有在线控制权。
11. CNEXT-CAM 通过版本化 Job Package 文件向 CNC_SYSTEM 交接任务，IPC 只发送通知；只有经 CNC_SYSTEM 校验并由操作员确认的任务才能进入本协议的 TASK_CREATE 阶段。
12. CQ8 在 HELLO_ACK 中返回 G 代码方言版本和能力摘要；任务所需 G/M 代码、循环、子程序或补偿能力超出 CQ8 能力时，CNC_SYSTEM 在 TASK_CREATE 前拒绝任务。

### 4.1 单连接消息调度要求

单连接方案下，PC 和 CQ8 都必须采用非阻塞收发、完整报文组帧和发送优先级队列。禁止在发送大块 G 代码时阻塞心跳、报警或控制响应。

建议发送优先级从高到低为：

1. 协议错误、连接关闭和安全状态事件；
2. 控制命令响应、报警和运行状态变化；
3. 心跳及缓冲区低水位/临界水位；
4. 周期状态；
5. G 代码 PROGRAM_CHUNK 和普通诊断日志。

约束：

- 单个 PROGRAM_CHUNK 的最大负载必须受限，防止一个大报文长期占用 TCP 发送队列；
- PC 发送器必须支持在程序分块之间调度高优先级消息；
- CQ8 接收线程只负责收包、校验和入队，禁止在网络接收线程中直接执行耗时 G 代码解析；
- 控制响应和报警不得等待整个程序分块窗口发送完成；
- TCP 字节流必须通过 Magic、HeaderLength 和 PayloadLength 正确拆包、粘包和重新同步；
- 单连接断开意味着控制、状态和程序通道同时失联，CQ8 必须依靠本地状态机和两级缓冲完成受控处理。

## 5. 连接状态机

```text
DISCONNECTED
    |
    | TCP连接成功
    v
TCP_CONNECTED
    |
    | HELLO / HELLO_ACK
    v
NEGOTIATED
    |
    | 身份、协议版本和能力兼容
    v
READY
    |
    +---- 任务建立 ----> TASK_READY ----> RUNNING
    |                                      |   |
    |                                      |   +--> HOLDING --> HELD
    |                                      +------> COMPLETED
    |
    +---- 超时/断线 ----> DISCONNECTED
    +---- 协议错误 -----> PROTOCOL_ERROR
```

约束：

- TCP 连接成功不代表允许发送控制命令；必须先完成协议协商。
- 协议主版本不兼容时拒绝进入 READY。
- 同一时间只能有一个 PC 会话持有控制权。
- 断线后不得自动恢复运动，必须重新核对任务和运行状态。

## 6. 报文通用结构

建议所有应用层报文使用固定头加可变负载：

| 字段 | 建议类型 | 说明 |
|---|---|---|
| Magic | `uint32` | 固定魔数，用于流重同步 |
| HeaderVersion | `uint16` | 报文头版本 |
| MessageType | `uint16` | 消息类型 |
| HeaderLength | `uint16` | 报文头长度 |
| Flags | `uint16` | 请求、响应、事件、错误等标志 |
| PayloadLength | `uint32` | 负载字节数 |
| SessionId | `uint64` | 当前连接会话标识 |
| Sequence | `uint64` | 发送方单调递增报文序号 |
| CorrelationId | `uint64` | 请求与响应关联号 |
| PayloadCrc32 | `uint32` | 负载 CRC32 |
| HeaderCrc32 | `uint32` | 报文头 CRC32 |
| Payload | 变长 | 具体消息内容 |

具体二进制布局、对齐、字节序和最大负载长度需在双方实现前冻结，并用同一组黄金报文测试。

## 7. 消息分类

### 7.1 连接与协商

| 消息 | 方向 | 作用 |
|---|---|---|
| HELLO | PC → CQ8 | 提交软件版本、协议版本和能力 |
| HELLO_ACK | CQ8 → PC | 返回 CQ8 版本、能力和兼容结果 |
| HEARTBEAT | 双向 | 业务层连接存活检查 |
| HEARTBEAT_ACK | 双向 | 心跳确认和当前状态摘要 |
| GOODBYE | 双向 | 正常关闭会话 |

### 7.2 任务与程序

| 消息 | 方向 | 作用 |
|---|---|---|
| TASK_CREATE | PC → CQ8 | 创建任务并提交程序元数据 |
| TASK_CREATE_ACK | CQ8 → PC | 接受或拒绝任务 |
| PROGRAM_CHUNK | PC → CQ8 | 下发完整程序或流式程序分块 |
| PROGRAM_CHUNK_ACK | CQ8 → PC | 确认接收、请求暂停或指定重发 |
| PROGRAM_COMMIT | PC → CQ8 | 声明程序末尾并请求整体校验 |
| PROGRAM_COMMIT_ACK | CQ8 → PC | 返回整体校验结果 |
| TASK_CANCEL | PC → CQ8 | 取消未运行任务 |

### 7.3 运行控制

| 消息 | 方向 | 作用 |
|---|---|---|
| RUN_PREPARE | PC → CQ8 | 请求执行前状态检查 |
| RUN_PREPARE_ACK | CQ8 → PC | 返回是否满足启动条件 |
| CYCLE_START_REQUEST | PC → CQ8 | 上位机提交启动请求 |
| FEED_HOLD_REQUEST | PC → CQ8 | 请求受控进给保持 |
| RESUME_REQUEST | PC → CQ8 | 请求从 CQ8 认可的恢复点继续 |
| CONTROLLED_STOP_REQUEST | PC → CQ8 | 请求受控停止 |
| RESET_REQUEST | PC → CQ8 | 请求复位允许软件复位的故障 |

PC 发出的运行命令均为请求，CQ8 必须根据机床状态、安全链和权限决定接受或拒绝。急停不通过普通 TCP 命令实现。

### 7.4 状态与报警

| 消息 | 方向 | 作用 |
|---|---|---|
| MACHINE_STATE | CQ8 → PC | 模式、运行状态和安全状态 |
| AXIS_STATE | CQ8 → PC | 轴位置、速度、使能和报警 |
| SPINDLE_STATE | CQ8 → PC | 主轴速度、方向和报警 |
| PROGRAM_STATE | CQ8 → PC | 接收、解析和执行位置 |
| BUFFER_STATE | CQ8 → PC | 两级缓冲水位和剩余时间 |
| IO_STATE | CQ8 → PC | 受控范围内的 IO 状态 |
| ALARM_EVENT | CQ8 → PC | 报警产生、变化和清除 |

## 8. G 代码程序分块

PROGRAM_CHUNK 负载至少包含：

| 字段 | 说明 |
|---|---|
| TaskId | 加工任务唯一标识 |
| ProgramId | 程序唯一标识 |
| ProgramVersion | 程序版本 |
| ProgramHash | 完整程序哈希 |
| ChunkSequence | 分块绝对递增序号 |
| StartBlockNumber | 本块第一条 G 代码的逻辑块号 |
| ByteOffset | 本块在完整程序中的字节偏移 |
| DataLength | 有效数据长度 |
| DataCrc32 | 本块 G 代码数据 CRC |
| IsFirst | 是否首块 |
| IsLast | 是否末块 |
| Data | G 代码字节数据 |

要求：

- CQ8 只能按已确认的 TaskId、ProgramHash 和 ChunkSequence 接收数据。
- 分块物理位置回绕不能导致序号回绕。
- 重复分块必须具备幂等性，不能重复写入或重复执行。
- 缺失分块时 CQ8 明确返回期望序号或缺失序号范围。
- PROGRAM_COMMIT 通过前不得把任务标记为完整下载。

## 9. 缓冲水位与流控

CQ8 应周期回传：

- 接收环形缓冲区总容量、已用容量和剩余容量；
- 接收缓冲区读写位置或对应绝对序号；
- 轨迹缓冲区剩余轨迹段数；
- 轨迹缓冲区预计可执行时间；
- 已接收、已解析和已执行 G 代码块号；
- NORMAL、HIGH、LOW、CRITICAL 水位状态。

推荐行为：

| 水位 | PC | CQ8 |
|---|---|---|
| HIGH | 暂停发送新分块 | 正常解析和消费 |
| NORMAL | 按窗口持续发送 | 正常执行 |
| LOW | 提高发送优先级并提示 | 继续执行并密切监控 |
| CRITICAL | 停止非必要通信 | 提前规划受控减速保持 |

不得等轨迹缓冲完全耗尽后再突然停止轴运动。

## 10. 确认、超时与重发

1. TCP 保证字节流可靠有序，但应用层仍需确认业务处理结果。
2. PROGRAM_CHUNK_ACK 表示 CQ8 已校验并接纳分块，不只是 TCP 已收到字节。
3. PC 维护有限的未确认发送窗口，不得无限制占用 CQ8 缓冲。
4. 应用层超时后先查询任务和缓冲状态，再决定重发。
5. 相同 TaskId、ProgramHash 和 ChunkSequence 的重发必须幂等。
6. 控制请求使用 CorrelationId 获取明确的接受或拒绝响应。
7. 超时参数必须可配置并由台架压力测试冻结。

## 11. 心跳与断线

待确认参数：

- 心跳周期；
- 连续丢失多少次判定断线；
- CONNECT、HELLO、普通请求和分块确认超时；
- 自动重连间隔与最大退避时间。

建议原则：

- 心跳负责发现应用层失联，TCP Keepalive 只作为补充。
- 缓冲充足时，短暂断线不直接打断 CQ8 当前轨迹。
- 轨迹进入临界水位时，CQ8 独立受控减速并进入 HELD。
- 重连后 PC 必须先执行状态同步，禁止直接补发或恢复。

## 12. 重连与状态同步

重连后 PC 发送状态同步请求，CQ8 返回：

- 当前 SessionId 和上一次会话终止原因；
- 当前 TaskId、ProgramId、ProgramVersion 和 ProgramHash；
- 已接收、已解析和已执行位置；
- 当前刀具、坐标系和关键模态状态；
- 当前机床模式、运行状态和报警；
- 是否存在 CQ8 生成的安全恢复点。

只有任务和程序身份完全一致，且 CQ8 明确允许时，PC 才能从指定序号续传。恢复运动还必须经过操作员确认。

## 13. 安全与权限

- 首期控制网络建议物理隔离或使用独立网段。
- 同一时间只允许一个控制会话。
- 未完成协议协商的连接只能获取有限诊断信息。
- 关键控制命令应记录用户、时间、请求号和执行结果。
- 程序哈希不一致时禁止启动、续传和恢复。
- TCP 控制命令不能替代急停、门锁、STO 和硬限位。
- 身份认证、消息认证和加密是否进入首期，由整机网络威胁评估决定。

## 14. 协议错误码分类

| 范围 | 分类 | 示例 |
|---|---|---|
| 1xxx | 连接与版本 | 协议版本不兼容、会话无效 |
| 2xxx | 报文格式 | 长度错误、CRC 错误、未知消息 |
| 3xxx | 任务与程序 | 任务冲突、哈希不一致、分块缺失 |
| 4xxx | 运行控制 | 状态不允许、权限不足、启动条件不满足 |
| 5xxx | 缓冲与流控 | 缓冲已满、序号超窗、轨迹水位不足 |
| 6xxx | 机床与安全 | 伺服报警、门锁、急停、安全链异常 |

完整错误码、中文提示、恢复建议和是否允许重试需另表维护。

## 15. 第一阶段协议验收

- 正常连接、协商和断开；
- 不兼容版本拒绝；
- 完整程序下载和整体哈希校验；
- 超过 10000 行程序的流式传输；
- 分块重复、缺失、CRC 错误和指定重发；
- 环形缓冲多次回绕；
- 高、正常、低和临界水位流控；
- PC 断线、崩溃和重启后的状态同步；
- CQ8 受控减速和 HELD 状态；
- 旧任务或错误程序哈希的续传拒绝；
- 控制请求接受、拒绝和超时；
- 长时间加工和短线段压力测试。
