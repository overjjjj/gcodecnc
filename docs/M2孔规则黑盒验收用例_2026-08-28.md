# M2 孔规则黑盒验收用例（2026-08-28）

## 1. 验收边界

本文件验证 M2 输入、规则选择、候选状态和确认适配合同，不验证私有实现。每个用例只观察 DTO 输出、状态、匹配解释、错误码和正式工序数量；不得检查内部调用顺序、私有类型布局或任何恢复代码。

- 测试资料使用 M0 版本化内存夹具或 JSON 夹具，不读取原始 Excel。
- 匹配阶段的正式工序数量必须始终为 0。
- 只有专门的确认适配用例可以调用既有人工确认链；任一失败必须保持正式工序数量为 0。
- `coolantCompat` 仅检查原值保留，不检查或改变冷却输出。
- 每个用例映射上位洁净规范 ID和证据类型；`推断`仍需产品/工艺评审批准。

## 2. 基础夹具约定

除用例另行覆盖外，基础夹具为：

- `asOfDate=2026-08-28`；材料、机床、刀具、规则资料版本均存在且已冻结。
- 已确认正面 +Z Setup；孔有稳定 `GeometryRef`、几何修订和层签名。
- 规则显式声明每层区间开闭、整数优先级、生效日期和 1–11 个标准化步骤。
- 不使用 `Hn` 或 `AT`；如需几何量，夹具使用语义已确认的结构化变量。
- 刀具类型、直径、刃长和总长满足目标步骤。

## 5. 原子确认验收合同

`M2-BB-ATOMIC-001` 匹配服务自身永远不创建正式工序；黑盒夹具在匹配后查询正式工序存储，数量必须不变。`[上位规范：DTM-CLN-COMMON-003；证据类型：说明书 + 推断]`

`M2-BB-ATOMIC-002` 确认适配器必须先验证候选状态、方案选择、全部表达式、全部刀具和全部参数，再进入正式创建；任何预校验失败时不得调用正式创建边界。`[上位规范：DTM-CLN-COMMON-006；证据类型：说明书 + 推断]`

`M2-BB-ATOMIC-003` 多步骤创建必须表现为单个原子结果：成功返回完整有序链，失败返回空链。用例不要求某种内部事务实现，只检查可观察结果。`[上位规范：DTM-CLN-COMMON-006、DTM-CLN-HOLE-004；证据类型：说明书 + Excel + 推断]`

## 6. 完成门

M2 实现只有在以下条件全部满足时可进入评审：

1. 本文件 44 个编号用例和 3 个原子合同均有自动化黑盒覆盖。
2. 每个非 `Draft` 结果具有稳定错误码、字段路径和匹配解释。
3. 区间开闭、优先级和生效日期全部来自显式 M0 DTO，没有行序或默认猜测。
4. 含未确认 `Hn/AT` 的规则不可启用。
5. 匹配阶段正式工序数量始终不变；确认失败正式工序链为空。
6. 没有 Excel 运行时读取、恢复代码、控制器文本或冷却执行变更。
