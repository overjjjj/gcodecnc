# CNEXT-CAM 整体框架与模块边界（2026-09-01）

## 1. 产品定位

CNEXT-CAM 是一套面向加工中心的独立 PC 工艺设计与程序验证软件，目标是简化传统 CAM 的操作步骤，同时保留加工安全、证据追溯和人工确认。说明书第七章是功能与工艺行为的主要依据；目标软件截图补充界面状态；Mastercam 公开流程只辅助优化操作方式，不定义本项目的工艺参数、刀路算法或控制器语义。

产品边界固定为一个 `CNEXT-CAM.exe`。PC 负责模型导入、工艺规划、刀路、后处理、验证和受控下发；CQ8 负责 G 代码解释、轨迹规划、实时插补、PLC、IO 和控制仲裁。PC 不承担伺服实时闭环。

## 2. 总体业务链

```text
STEP / 项目
  → Setup 与坐标系
  → 几何和拓扑识别
  → 公共选择会话
  → Selection Candidate / Recognized Feature
  → 规则匹配、刀具与参数建议
  → Operation Proposal
  → 人工确认
  → OperationFactory 原子创建正式工序
  → Strategy 生成控制器无关刀路
  → PostProcessor 生成目标控制器代码
  → GCodeSafetyValidator
  → 基于最终代码的仿真
  → Program Snapshot
  → 人工装载或受控发送至 CQ8
```

这条链有三道不可跨越的边界：

1. **识别与选择边界：**识别、串联、规则和自动推荐只能输出候选，不能创建工序。
2. **人工确认边界：**只有当前候选、刀具、参数和来源版本全部通过校验后，才可由 `OperationFactory` 原子创建正式工序。
3. **控制器边界：**只有最终后处理代码通过安全检查和最终代码仿真后，才可形成不可变程序快照并进入发送流程。

## 3. 分层架构

| 层级 | 主要职责 | 代表模块 | 明确禁止 |
| --- | --- | --- | --- |
| 表现与交互层 | 模型显示、选择操作、参数编辑、候选解释、工序树、预览与状态展示。 | `src/ui`、`ViewportWidget`、各类 Dialog/Panel。 | 在 UI 中生成刀路、拼接 G-code 或直接写正式工序。 |
| 应用服务层 | 编排选择会话、规则匹配、候选调和、参数查询、人工确认事务和程序生成。 | `src/services`。 | 越过服务边界读取 UI 状态；候选服务调用正式工序或控制器接口。 |
| 领域核心层 | Setup、稳定引用、候选、工序、参数、项目快照和状态等稳定业务对象。 | `src/core`、`src/strategies/OperationProposal.*`、`MachiningOperation.h`。 | 引入 UI、通信或控制器实现。 |
| 几何与识别层 | STEP 导入、孔/槽/型腔识别、拓扑证据、二维刀具中心安全区域。 | `src/import`、`src/core/geometry2d`。 | 根据不完整证据直接宣布可加工或创建工序。 |
| 工艺策略层 | 针对已确认工序生成控制器无关的切削与连接运动。 | `src/strategies/hole`、`src/strategies/mill`。 | 读取界面控件、自动换工艺、直接发送 CNC。 |
| 后处理与程序层 | 将已验证刀路转换为 CQ8/Fanuc/Siemens 代码，形成程序包和快照。 | `src/postprocessor`、`src/gcode`。 | 修改工艺意图、补猜刀具或绕过安全校验。 |
| 验证与执行边界 | 最终代码安全检查、仿真、CQ8 通信和受控状态展示。 | `src/simulation`、`src/communication`。 | 用内部策略预览替代最终代码仿真；PC 承担实时运动控制。 |
| 持久化与配置层 | 项目、模板、刀具资料、Machine Profile、版本与哈希。 | `ProjectManager`、模板与刀具库模块。 | 静默升级版本、丢失来源或覆盖已确认工序。 |

依赖方向原则为：交互层和应用层可以依赖领域接口；几何、策略、后处理和通信通过明确 DTO/端口连接。控制器、冷却、后处理和正式工序类型不得反向进入选择候选的公开接口。

## 4. 核心领域对象

| 对象 | 含义 | 生命周期位置 |
| --- | --- | --- |
| `Setup` | 一次装夹所使用的加工方向和工件坐标系。 | 所有选择、识别、工序和程序的基础上下文。 |
| `StableSelectionRef` | 包含几何、拓扑、Setup、来源类型及来源对象版本的稳定选择引用。 | 从选择开始保留到候选失效检查。 |
| `TopologyEvidence` | 带 revision、provenance、toleranceSource 的环、岛、分支或自由端证据。 | 由几何解析边界提供，候选服务只消费、不猜测。 |
| `SelectionSession` | 记录来源选择、串联、分支、起点、方向、排序、撤销等显式用户事件。 | 只存在于公共选择阶段。 |
| `SelectionCandidate` | 选择完成后的不可执行结果，保存引用、顺序、加工侧和拓扑证据。 | 选择层输出；不能进入刀路。 |
| `RecognizedFeature` | 孔、槽、型腔、平面或轮廓等几何加工候选。 | 识别层输出。 |
| `RuleMatch` | 版本化规则的唯一命中、冲突或拒绝解释。 | 自动工艺规划阶段。 |
| `OperationProposal` | 包含可选策略、刀具和参数快照的非执行建议。 | 人工确认之前。 |
| `MachiningOperation` | 经人工确认、具有几何、策略、刀具、参数和阶段的正式工序。 | 只能由 `OperationFactory` 创建。 |
| `ToolpathResult` | 针对一个正式工序生成并验证的控制器无关运动序列。 | 策略层输出。 |
| `ProgramSnapshot` | 最终控制器代码以及其工序、Machine Profile 和生成设置的不可变记录。 | 安全检查和仿真通过之后。 |

候选状态统一使用 `Draft`、`Selected`、`Conflict`、`Stale`、`Rejected`；`Validated` 和 `Confirmed` 只属于人工确认之后。无法证明的情况返回稳定问题码和字段路径，不用默认值或启发式继续加工。

## 5. 工艺模块框架

### 5.1 P0：孔与孔自动化

```text
CompoundHoleRecognizer
  → 孔层及同轴证据
  → AutoHoleRuleMatchingService
  → AutoHolePlanningService
  → 候选重识别与人工覆盖调和
  → 人工确认适配器
  → OperationFactory
  → 钻削/深孔/扩孔/铰孔/攻丝/铣牙策略
```

当前已具有孔识别、固定循环、多层孔候选、M0 模板、M1 刀具切削参数、M2 规则匹配和 M2.1 候选调和基础。后续重点是 selector 到真实刀具目录的严格解析、人工确认原子事务及端到端最终代码验收。`Hn/AT`、未确认参考面的深孔阶段、侧孔和斜轴继续阻断。

### 5.2 P1/P2：型腔与槽

```text
SelectionSession
  → StableSelectionRef
  → ISelectionReferenceResolver
  → versioned TopologyEvidence
  → PocketSelectionCandidate / SlotSelectionCandidate
  → 人工确认后的工艺计划
  → OperationFactory
  → Pocket / Slot Strategy
```

公共选择层与现有 `SlotFramePlanningService::Confirm()` 必须隔离：前者只能产生候选；后者会进入正式工序链，只能在后续明确人工确认后使用。`SelectionChainController::commit()` 生成的随机 UUID 和无版本几何列表不能作为稳定业务引用。

首批安全范围：

- 型腔：Front `+Z`、完整闭合外环、无自交/退化、最多一个可证明且严格包含的孤岛。
- 槽：直闭槽、矩形闭槽；简单开放槽只生成带 `OPEN_SLOT_PERSISTENCE_UNCONFIRMED` 的内存阻断候选。
- 暂不开放：动态起点、几何自动排序容差、开放槽持久化、凹多解偏置、动态铣、曲面底、侧面和多轴。

当前 P1/P2 公共选择开发按 B0–B5 分批：

| 批次 | 内容 | 当前门禁 |
| --- | --- | --- |
| B0 | 核心值 DTO、只读 resolver 端口、candidate-only 服务边界。 | 最终 RED 已通过，只批准最小 GREEN。 |
| B1 | `BeginSelection`、来源选择、稳定引用和 Front `+Z` 校验。 | 未批准实现。 |
| B2 | 串联、分支、起点、反向、撤销/恢复和显式事件顺序。 | 未批准实现。 |
| B3 | 型腔闭环、单孤岛候选及拓扑拒绝。 | 未批准实现。 |
| B4 | 闭槽候选、开放槽 blocked candidate。 | 未批准实现。 |
| B5 | 工程注册、全量回归、公开头依赖和集成验收。 | 未批准实现。 |

### 5.3 后续模块

- 牙类：正面内螺纹的攻牙和铣牙；规格、螺距、底孔和刀具必须精确可追溯。
- 倒角与清角：优先维护二维安全子集；一般三维倒角和自动插角继续阻断。
- 刻字：需先冻结字体/轮廓来源、许可、版本和二维轮廓合同。
- 斜面、圆角和复杂三维：当前不抢占孔、型腔、槽的开发容量。

## 6. 工艺参数框架

各工艺不直接维护自由散落的参数，而是复用统一结构：

```text
公共参数
  Setup / 坐标系 / 安全高度 / 目标深度 / 材料 / 机床
几何参数
  稳定引用 / revision / 边界 / 岛 / 自由端 / 尺寸证据
刀具参数
  类型 / 直径 / 有效刃长 / 总长 / 角度 / 精确目录引用
切削参数
  转速 / 进给 / stepOver / stepDown / 余量 / R 平面 / Q
策略参数
  粗精阶段 / 方向 / 起点 / 进退刀 / 排序
来源参数
  规则 / 模板 / 刀具目录 / provenance / toleranceSource / 版本
```

参数默认值只能来自说明书、版本化模板、规则或刀具资料；来源缺失、单位不明、区间不明或多条同优先级匹配时，返回候选冲突或拒绝，不静默补值。

## 7. UI 与用户操作框架

一级工作区保持：

1. **工艺设计：**导入模型、Setup、特征/区域选择、工艺建议、刀具参数和工序树。
2. **程序验证：**刀路预览、材料/碰撞验证、最终代码、安全结果和程序快照。
3. **机床运行：**CQ8 连接、模式、任务、坐标、缓冲、报警和受控请求。

工艺设计采用简化 CAM 心智：

```text
选择加工对象
  → 系统识别并解释候选
  → 用户选择加工方式
  → 确认刀具与关键参数
  → 预览和验证
  → 生成人工确认的正式工序
```

“路径预览”“材料/碰撞验证”“最终控制器代码仿真”必须分层显示，前一层通过不能替代后一层。推荐必须可解释、可撤销、可编辑，错误状态不能伪装成可加工结果。

## 8. 测试与安全门

每个功能严格执行：

```text
说明书/洁净合同
  → 真实 DTO 黑盒 RED
  → 最小 GREEN
  → 聚焦单元测试
  → 架构边界审核
  → Qt/MinGW Debug 构建
  → 相关模块回归
  → 工程注册
  → 最终代码安全与仿真
  → 受控机床试切
```

测试分为五层：领域值对象、应用服务黑盒、策略/几何、最终代码和系统验收。测试不得把 scenario、expected result 或错误码作为生产输入，也不得为观察副作用给生产 DTO 添加计数器。

冷却逻辑继续冻结。选择、规则、候选和参数服务只能携带兼容性资料，不能修改冷却指令或默认行为。涉及刀路和 G-code 的后续提交必须额外执行特征边界、安全高度、快速移动、后处理和最终代码仿真审查。

## 9. 开发与审核组织

| 角色 | 职责 | 禁止事项 |
| --- | --- | --- |
| 当前方案窗口 | 说明书对照、术语与范围确认、架构裁决、阶段门禁和集成决策。 | 直接扩大已批准批次或绕过审核。 |
| 方案/审核线程 | 拆分执行步骤、检查依赖和代码边界、复核测试与提交。 | 直接修改生产实现、合并或推送。 |
| 编码/测试线程 | 按批准批次先写 RED，再做最小实现、构建和回归。 | 未经批准进入下一批、修改冷却或夹带重构。 |
| 集成人 | 核对提交范围、处理工程注册、回归和最终合入。 | 把脏文件、其他工作树改动或未验收能力带入集成。 |

每个批次使用小提交并保留 RED、GREEN、注册和验收证据。子线程不得自行 merge/push；只有当前方案窗口确认审核结论后才能进入下一批。
