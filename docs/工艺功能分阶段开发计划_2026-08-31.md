# 工艺功能分阶段开发计划（2026-08-31）

## 1. 基线、范围与交付原则

基线为已提交的 M0、M1、M2 及 M2.1 洁净规格。M2.1 的 16 条 `M21-IF-*` 接口规则和 34 个黑盒用例是孔类下一批的冻结输入，不代表已经实现。计划只安排公开接口内的工作；不读取 DTM 反编译伪代码，不在运行时读取 Excel，不修改冷却代码或行为。

各阶段沿用以下完成门：先为新增合同写 RED 测试，最小实现至 GREEN，做 Google C++ 风格复审；再运行模块回归、`build_pipeline_test`、Debug 增量构建与 `git diff --check`。候选服务不得创建正式工序；确认适配层必须证明失败时工序数不变。

## 2. 交付阶段与接口所有权

| 阶段 | 目标与安全交付物 | 主要接口所有权 | 不在阶段内 |
| --- | --- | --- | --- |
| P0：公共收口 | 固定候选快照、版本解析、来源/错误解释和确认适配器需求。 | Automation Core：M0 DTO、JSON、M1、候选状态。 | 运行时 Excel、冷却变更。 |
| P1：孔闭环 | 实现 M2.1 调和；在获授权后将唯一、可确认候选接到原子 `OperationFactory` 适配；回归固定循环。 | Hole Planning：M2/M2.1； Integration：确认事务、既有孔策略。 | Hn/AT、未批准 selector 等价、深孔阶段。 |
| P2：牙类 | 版本化 `ThreadSpecification` 使用、内牙攻丝/铣牙候选与人工确认闭环。 | Thread Planning：规格/规则； Toolpath：既有攻丝/螺纹铣策略。 | 外牙、锥牙、未知控制器循环、吊环孔双版本自动化。 |
| P3：二维倒角/清角 | 统一二维倒角 proposal；将已验收清角限制固化为可审计子集。 | Contour Planning：特征/参数； Toolpath：轮廓和二维几何。 | 3D 倒角、插角、动态铣。 |
| P4：槽/型腔 | 为槽框/型腔增加规则和 M1 选刀适配，保持二维安全子集。 | Slot/Pocket Planning：识别与规则； Toolpath：槽/腔策略。 | 曲面底、未持久化开放槽、凹多边形动态铣。 |
| P5：二维刻字 | 冻结字体轮廓来源后，交付正面二维刻字候选、确认和轮廓刀路。 | Engraving Planning：字体/DTO； Toolpath：二维轮廓。 | 曲面刻字、位图矢量化、自动排版。 |
| P6：集成验收 | 跨模块快照、过期、项目重开、三后处理器、安全与仿真回归。 | Integration/QA：项目、生成、安全、仿真。 | 以通过回归替代机床验收。 |
| P7：独立立项 | 复杂 3D、侧面/多轴、圆角、动态铣、Hn/AT、生产容差。 | Geometry/Simulation/Controller 专项。 | 纳入本计划的交付日期。 |

### 分支与提交顺序

每个阶段用独立短期分支，例如 `codex/holes-m21-reconciliation`、`codex/thread-v1`、`codex/chamfer-2d-v1`、`codex/slot-pocket-v1`、`codex/engraving-2d-v1`。共享文件由接口所有者预约，避免并行编辑 `OperationFactory`、策略注册、项目保存和测试脚本。

每项功能按以下小提交顺序提交，禁止 `git add -A` 或 `git add .`：

1. `test(<module>): define <contract>`：仅精确暂存新增/调整测试，确认 RED。
2. `feat(<module>): <minimal behavior>` 或 `fix(<module>): <safety rule>`：仅暂存实现与必要公共 DTO，确认 GREEN。
3. `chore(<module>): register <test>`：仅在确需工程注册时单独提交。
4. `docs(<module>): record <acceptance>`：验收矩阵、阻断项、验证证据和项目进度。

候选到确认的共享适配器只能在 P1 通过独立设计评审后合入；后续模块只能调用已冻结的确认入口，不直接触碰工序仓储。

## 3. 单人排期（保守 30–34 周，含评审缓冲）

| 周 | 重点 | 可验收里程碑与缓冲 |

| 3–7 | P1 M2.1 候选调和 | 34 项黑盒 RED/GREEN；仅候选零副作用。 |
| 8–9 | P1 确认适配设计与孔集成 | 仅在业务授权后实现原子确认；否则作为显式阻断验收。 |
| 10 | 孔类回归与评审缓冲 | 真实 STEP、三后处理器、安全、仿真；修复仅限已批准合同。 |
| 11–14 | P2 牙类候选与资料快照 | 内牙攻丝/铣牙安全子集、规格/刀具拒绝测试。 |
| 15 | 牙类集成与评审缓冲 | 程序、安全、仿真和项目重开回归。 |
| 16–18 | P3 二维倒角/清角 | 外倒角闭环；清角是否开放由前序证据/持久化门决定。 |

| 20–24 | P4 槽/型腔规则与选刀 | 槽框/保护区/刀具包络、确认与最终代码回归。 |

单人关键路径是“孔确认事务授权 → 孔闭环 → 牙类/二维倒角 → 槽/型腔 → 刻字”。若 P1 授权未到位，仍可完成 M2.1 候选调和和 P3 的纯二维安全工作，但不得声称孔已闭环。

## 4. 三人并行排期（保守 16–19 周，含评审缓冲）

角色按接口而非按人固定：A 负责 Automation/Hole、B 负责 Thread/Contour、C 负责 Slot/Pocket/Integration。共享 `OperationFactory`、项目保存、策略注册、后处理和测试脚本由当周轮值集成人一次变更，其他人只提交各自服务/测试/文档。

| 周 | A：Automation/Hole | B：Thread/Contour | C：Slot/Pocket/Integration |
| --- | --- | --- | --- |
| 1–2 | M2.1 夹具与 34 项 RED | 牙类规格/现有策略边界审计 | 槽/型腔、二维几何和集成基线审计 |
| 3–5 | M2.1 最小调和 GREEN | 内牙候选、规格/刀具拒绝 | 槽/型腔规则 DTO 与只读选刀适配 |
| 6 | 孔类评审缓冲 | 牙类评审缓冲 | 槽/型腔评审缓冲 |
| 7–8 | 确认事务设计或阻断测试 | 攻丝/铣牙确认闭环 | 槽/型腔确认与策略回归 |
| 9–10 | 孔真实 STEP/最终代码回归 | 二维外倒角 proposal 与回归 | 槽/型腔保护区、三后处理器回归 |

| 15–16 | 最终安全/仿真回归 | 最终安全/仿真回归 | 最终安全/仿真回归 |
| 17–19 | 评审与机床验收准备缓冲 | 评审与机床验收准备缓冲 | 评审与机床验收准备缓冲 |

## 5. 阶段测试矩阵与完成定义

| 验收面 | P1 孔 | P2 牙类 | P3 倒角 | P4 槽/型腔 | P5 刻字 |
| --- | --- | --- | --- | --- | --- |
| DTO/JSON/版本 | M0/M2/M2.1、34 黑盒 | 规格、螺距、来源 | 参数/工具快照 | 规则/几何引用 | 字体/轮廓版本 |
| 几何与规则 | 层连续、版本调和、唯一命中 | 孔证据、规格唯一 | 平面凸环/前序证据 | 环、保护区、自由端 | 受控二维轮廓 |

## 6. 业务确认门与风险登记

| 确认门 | 影响阶段 | 未获得确认时的计划动作 |
| --- | --- | --- |
| selector 的精确等价/替代关系 | P1–P5 | 不实施自动实体选刀；返回 `Conflict`。 |
| 跨版本人工覆盖迁移 | P1 | 不迁移步骤、进给、转速、刀具或方案覆盖。 |
| `Conflict/Stale` 重处理授权、审计和确认事务 | P1 及所有后续模块 | 候选服务保持零正式工序；确认适配不合入。 |
| Hn/AT、深孔参考面、控制器能力 | P1 | 深孔/表达式保持拒绝。 |
| 生产容差来源与比较规则 | 全部几何模块 | 不引入“接近即可”的匹配。 |
| 螺纹/吊环孔双版本权威性 | P2 | 仅支持已明确的人工确认内牙子集。 |
| 字体许可与版本化轮廓源 | P5 | 刻字只完成接口/拒绝测试，不生成刀路。 |
| 三维拓扑、运动学、碰撞和后处理合同 | P7 | 复杂三维、侧面多轴、圆角、动态铣持续阻断。 |

## 7. 本计划的完成标准

本计划完成不等于开放全部工艺类型。完成的可度量定义是：孔、牙类、二维倒角、二维槽/型腔和二维刻字各自只在已批准安全子集内形成“识别/候选 → 人工确认 → 正式工序 → 策略 → 最终代码安全与仿真”的可追溯闭环；所有超出子集的输入都有稳定拒绝；冷却行为、UI 自动化、后处理语义和复杂三维能力未被意外改变。
