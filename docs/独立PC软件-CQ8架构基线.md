# 独立PC软件-CQ8架构基线

## 当前权威决定

自 2026-08-04 起，本项目的软件实现基线固定为：

- 唯一代码基准：`D:\yanggao\gcodecnc\untitled`；
- 唯一 PC 产品：`CNEXT-CAM.exe`；
- PC 软件直接通过受控通信模块连接自研 CQ8 驱控一体系统；
- 不引入、不复制、不链接、不启动 `D:\yanggao\CNC_SYSTEM` 的代码或可执行程序；
- 不把 CNC_SYSTEM 作为本产品的进程、运行时、界面或交付依赖；
- CQ8 继续负责 G 代码解释、轨迹规划、实时插补、PLC、IO 和控制仲裁；
- Windows PC 不承担伺服实时闭环。

本文件取代此前关于“CNEXT-CAM 与 CNC_SYSTEM 双进程协同”的讨论和草案。旧文档中出现的 CNC_SYSTEM、跨软件 Job Package 或本地 IPC 交接内容不得作为开发依据。

## 单软件内部模块边界

`CNEXT-CAM.exe` 内部按模块隔离，而不是引入第二套软件：

1. **工艺设计模块**：模型、Setup、特征、工艺、刀具和参数；
2. **程序验证模块**：CQ8 G 代码、程序快照、仿真、安全校验和追溯；
3. **在线控制模块**：CQ8 TCP、整包/流式下发、状态、报警和恢复请求；
4. **机床运行界面**：连接、模式、任务、坐标、缓冲和受控请求；
5. **项目与配置模块**：项目文件、Machine Profile、机床配置包和版本哈希。

模块可以使用独立线程和服务对象，但保持同一代码库、同一安装包和同一产品进程边界。若未来确需拆分辅助进程，必须另行形成架构决策，不能复用其他项目作为默认方案。

## 程序数据流

```text
STEP/项目
  -> Setup与人工特征选择
  -> 工艺、刀具和参数确认
  -> CQ8目标G代码
  -> Program Snapshot与安全校验
  -> 程序验证/仿真
  -> 在线控制模块人工装载
  -> 整包下载或旋转缓冲流式下发
  -> CQ8执行
```

单软件内部不需要跨软件 Job Package。仍需保留不可变 Program Snapshot、ProgramHash、OperationId 和执行任务状态，确保设计修改不会静默改变正在运行的程序。

## UI基线

一级工作区固定为：

1. 工艺设计；
2. 程序验证；
3. 机床运行。

所有工作区共享常驻状态头部，至少显示：

- CQ8 连接；
- 机床模式；
- 当前任务；
- 安全状态。

在真实 CQ8 协议、安全链和实体面板完成联调前，机床运行页的运动请求按钮保持禁用，不用占位界面伪装已经具备控制能力。

## 当前仍有效的总体决定

- Windows x64 PC；
- CQ8 自有、版本化 G 代码方言；
- 首期仅毫米 `G21` 和绝对模式 `G90`；
- CQ8 接受 I/J/K 和 R，CNEXT-CAM 生成 I/J/K；
- 单个 TCP 长连接消息复用；
- 大程序支持持续流式下发；
- CQ8 内部分开 G 代码接收环形缓冲和轨迹规划缓冲；
- 手轮、点动和回零直接进入 CQ8；
- 急停、门锁和 STO 由独立硬件安全链处理；
- 首期 X/Y/Z 三轴、一个主轴和自动刀库；
- 现场辅助设备通过机床配置包适配，不提前硬编码。
