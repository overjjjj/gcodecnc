# M2.1 孔候选重识别黑盒验收（2026-08-31）

## 1. 验收边界

本矩阵只观察不可变请求、`CandidateReconciliationResult`、候选状态、人工覆盖处置、差异解释、错误码、字段路径及正式工序数量。夹具使用已冻结 M0 DTO 和内存/JSON 资料快照，不读取 Excel，不检查私有实现。

- 每一项调和用例执行后正式工序数必须为 0；M2.1 不调用 UI、`OperationFactory`、刀路、后处理、控制器或冷却。
- 除另有说明，旧候选和当前观测的所有引用可解析，当前特征为合法正面 +Z 孔，且当前规则匹配已完成。
- 每个用例的错误/差异解释应包含 `requestId`、`candidateId`（适用时）、稳定错误码和字段路径。

## 3. 完成门

M2.1 实现进入评审前必须满足：

1. 本表 43 个用例均有自动化黑盒覆盖，且不依赖 Excel、UI 或恢复代码。
2. `Draft`/`Selected` 保留只发生在同一可复用方案；无覆盖时处置为 `None`。
3. 可解析差异为 `Conflict`，不可解析/撤回引用为 `Stale`，二者不以当前最新版本替代。
4. 取消沉头只过滤标志步骤，空链稳定拒绝；特征或计划变化不静默迁移。
5. 每个负向结果具有稳定错误码、字段路径与安全差异解释，且正式工序数保持为 0。
6. 所有 selector、跨版本覆盖迁移、人工重处理授权和确认事务的未确认语义保持阻断。
7. `Stale` 恢复必须使用必填 `lastEditableState` 和（适用时）精确 `selectedPlanRef`；解析视图必须完整且键唯一。
