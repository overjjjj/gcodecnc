# DTM 交付包复用评估与接入清单

## 目的与边界

本清单整理 `DTM_分析交付包_2026-08-21/02_设计界面` 中可用于 CNEXT-CAM 的参考资料。恢复源码来自 EXE/DLL/PDB 的反编译，不是可编译的原始源码；只能用来核对入口、参数和交互，不得直接编译、复制到生产代码或绕过安全校验。

原始文件由 `MANIFEST_SHA256.txt` 校验；外部原件保持只读，不把 EXE、DLL 或反编译伪代码纳入产品构建。

## 复用结论

| 来源 | 可直接使用 | 使用方式 | 禁止事项 |
|---|---|---|---|
| `DESIGN_INTERFACE_FUNCTIONS.md` | 是 | 第七章功能、参数和 DTM 入口的需求基线 | 不把入口名称当作已实现算法 |
| `DESIGN_INTERFACE_UI_SPEC.md` | 是 | Ribbon、面板、选择链和参数表单的 UI/数据规格 | 不覆盖本项目现有安全交互 |
| `FUNCTION_INDEX.md`、`CATDESIGN_FUNCTION_MAP.md`、CSV 清单 | 是 | 需求追溯和遗漏功能盘点 | 不依赖地址或反编译类型定义 |
| 恢复的 `CatDesign`、自动孔、智能倒角、几何 `.cpp` | 否（仅参考） | 提取参数名、调用顺序、状态机和拒绝条件后重新设计并测试 | 不能直接拷贝到 `untitled/src`；不能把伪代码视为真实几何算法 |
| 测试软件的 README、验收脚本 | 是（仅作验收模板） | 复用界面分组、脏状态、批量工序、参数拒绝和离屏截图的测试思想 | 不能把模拟 `DesignModel` 当作 CAM 领域模型 |
| 测试软件 EXE、Qt DLL、平台插件 | 否 | 仅供外部演示对照 | 不复制到项目、不随 CNEXT-CAM 发布 |

## 当前可直接接入的参考项目

1. **功能追溯表**：以 `FUNCTION_INDEX.md` 和 `design_interface_functions.csv` 作为第七章到 CNEXT-CAM 功能状态的证据索引。
2. **UI 验收模板**：以测试软件的五个场景补充 CNEXT-CAM 的 UI 合同：十个 Ribbon 分组、四个主要区域、创建工序后的脏状态、自动孔批量候选、步距不大于刀径、离屏渲染。
3. **自动孔参数字典**：恢复 `ModuleAutoHole::WorkParams` 可用于核对字段缺漏，例如模板、直径、刀具、起始层、深度、速度、单次深度、步距、精加工余量、斜面和圆角字段；字段仍必须映射到 `ProcessParameterSchema` 并受安全校验。
4. **反编译入口矩阵**：后续新增功能必须在验收记录中链接 DTM 入口，例如 `dynamicMilling`、`millClearInnerCorner`、`millChamfer3D`、`millFilletedCorner`、`featuresHole`、`intelligentChamfering`、`autoSlotFrame`。

## 当前不可直接实现的能力

- 3D 斜面、圆角、3D 倒角：恢复资料没有可验证、可移植的 STEP 曲面偏置与碰撞算法；继续保持禁用。
- 动态铣、复杂孤岛、清内角、空间曲线：只有在稳定几何边界、刀具中心包络和最终仿真合同建立后才开放。
- G76、外螺纹、多齿螺纹：缺少完整机床/Setup/刀具几何合同，继续安全阻断。
- 自动框、复合孔、智能倒角刀路：可保留候选和规则界面，但不能直接生成正式刀路。

## 后续接入顺序

1. 把上述文档与清单作为工作树内的只读参考归档。
2. 将测试软件的“UI 分组、脏状态、参数拒绝、离屏截图”转写为 CNEXT-CAM 的实际 UI 合同测试，不导入其模拟业务代码。
3. 用恢复源码的参数/状态信息补齐每个未完成功能的需求与拒绝条件；先写 CNEXT-CAM 测试，再新写实现。
4. 每次开放原本阻断的路径时，必须同时通过最终 CQ8 输出、安全检查、仿真和项目保存重开验证。
